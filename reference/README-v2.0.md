# تحدّي التوجيهي | التربية الإسلامية

**إنشاء الطالب أيوب محمد البطوش**

نسخة مطوّرة من ملف HTML المرفق نفسه، وليست نموذجًا تجريبيًا ببيانات طلاب وهمية. المحتوى من كتاب **الصف الحادي عشر / الفصل الثاني**؛ اسم «التوجيهي» اسم المشروع ولا يجعله امتحانًا رسميًا للثاني عشر.

## البدء السريع على ويندوز

1. فك ضغط `islam-release.zip` في مجلد ثابت.
2. افتح `standalone.html` بمتصفح حديث. كل الشيفرة والبيانات داخل الملف؛ لا يلزم اتصال لتشغيله.
3. للحفظ الأكثر استقرارًا والتطوير، ثبّت **Node.js 24 LTS** ثم افتح PowerShell داخل مجلد المشروع وشغّل:

```powershell
npm ci
npm run build
npm start
```

يعرض الأمر الأخير عنوان الخادم المحلي على المنفذ 4173. اترك النافذة مفتوحة أثناء الاستعمال، وأوقفها بـ Ctrl+C. يمكن أيضًا تشغيل `node scripts/serve.mjs` دون تنزيل أي حزم إذا كانت نسخة `dist` موجودة.

**مهم:** لم يمكن اختبار فتح `file://` في Chromium المُدار هنا لأن سياسة المتصفح تمنعه. اختُبرت الحزمة المدمجة دون طلبات خارجية، واختُبر التطبيق عبر خادم محلي. التخزين في ملفات HTML المحلية يختلف بين المتصفحات ومسارات الملفات؛ لا تعتمد عليه وحده. صدّر نسخة تقدم من الإعدادات قبل نقل الملف أو تغيير المتصفح أو مسح بياناته.

## استخدام المنصة

- اختر اسمًا مستعارًا أو تابع كضيف. لا يُرسل الاسم أو التقدم إلى خادم.
- اختر الوحدة والدرس والمستوى والوقت. جميع الدروس متاحة.
- الأنواع الستة لها تفاعل أصلي: اختيار فردي، صح وخطأ، إكمال بالاختيار، اختيار متعدد، توصيل، ترتيب.
- الأجوبة الفردية تنتقل تلقائيًا؛ الأسئلة المركبة تنتظر الاكتمال. التغذية الراجعة الفورية اختيارية في التدريب الحر فقط.
- في **تحدي لاعبين | 1 ضد 1**: العدد لكل لاعب، ويضاعف للإجمالي؛ لا يبدأ المؤقت قبل «أنا جاهز». النقاط والإجابات والشروح في النهاية.
- **الامتحان 45 دقيقة إجماليًا**، مع المستوى والنطاق المختارين. يمكنك الرجوع والتعديل، ولا يُسلّم بمجرد الإجابة عن السؤال الأخير. الوقت يستمر خارج شاشة اللعب.
- الجولة العادية تُوقف عند الخروج مع الحفظ، ويستمر توقيت السؤال عند إخفاء التبويب. يمكن إنهاء الجولة مبكرًا بتأكيد.
- تتجدد الأسئلة وفق سجل محلي مشترك للنطاق والمستوى؛ لا تكرار داخل الجولة. المخزون محدود، ويبدأ دوران جديد بعد نفاده. البقاء/القلوب ينتهيان عند نفاد الأسئلة الفريدة.
- التحدي اليومي 10 والأسبوعي 20 سؤالًا، ومكافأة XP مرة في الفترة. ليسا مسابقة خادمية موحدة بين المستخدمين.
- في السياقات التي تدعم Web Locks، يمنع فتح تبويبين كاتبين في الوقت نفسه لحماية التقدم. إذا لم يتوفر القفل، يظهر تنبيه ويجب استعمال تبويب واحد فقط.
- حفظ النتائج والأخطاء والإنجازات والجلسة الجارية في IndexedDB، مع بديل localStorage وتنبيه للحفظ المؤقت. الاستيراد يتحقق من الملف ويطلب التأكيد قبل الاستبدال.
- المؤثرات رقمية قصيرة، مع تحكم بالكتم، **دون موسيقى**.

## بنية المشروع

```text
src/core.js          التحقق والخلط والنقاط والإحصاءات الأساسية
src/controller.js    الجلسات والأدوار والمؤقت والامتحان والأفعال
src/storage.js       قاعدة البيانات والبديل والتحقق من النسخ الاحتياطية
src/ui.js            الصفحات والتفاعلات والأصوات والإنجازات
src/styles.css       نظام التصميم والتجاوب والوضعان
scripts/build.mjs    بناء HTML مكتفٍ ذاتيًا
scripts/serve.mjs    خادم ملفات محلي دون تبعيات تشغيل
scripts/audit-content.py تدقيق البيانات ونطاق صفحات PDF
scripts/source-alignment.py مقارنة لفظية لكل البنك مع PDF
data/                البنك الكامل والمؤهل والمسودات والأدلة
reference/original.html نسخة المرفق الأصلية للمقارنة
index.html           ملف مولّد؛ لا تعدله يدويًا
standalone.html      نسخة مستقلة مولّدة
dist/index.html     نسخة الإنتاج للنشر
tests/               اختبارات المحرك والتخزين والمتصفح
artifacts/           نتائج المتصفح وصور الشاشات
```

استخدم checkout الموجود في المهمة المعزولة؛ لا حاجة إلى Git worktree. عدّل مصادر `src` أو `data` ثم أعد البناء. البيانات المستمرة منفصلة عن ملفات الإنتاج ولا يمسحها البناء. يُحتفظ باسم قاعدة البيانات والمفتاح من الإصدار الأصلي. تختلف مساحة التخزين بين الأصول/المنافذ والبروتوكولات؛ انتقل بين الأجهزة بالتصدير والاستيراد.

## الاختبارات

```powershell
npm test
npm run build
npm start
# في نافذة أخرى:
npx playwright install chromium
npm run test:browser
```

على الأنظمة التي توفر Chromium مسبقًا، عيّن `CHROMIUM_PATH` عند الحاجة. يستخدم الاختبار `/usr/bin/chromium` تلقائيًا إن وُجد. الحد الأدنى لأمر الاختبارات Node 22.8؛ Node 24 هو الخيار الموصى به. راجع `TEST_RESULTS.md` لنتائج التنفيذ الفعلية وحدود الاختبار، لا لمجرد الأوامر المقترحة.

تدقيق PDF الاختياري يحتاج Python 3 وPyMuPDF:

```powershell
python -m pip install pymupdf
python scripts/audit-content.py --pdf "مسار الكتاب.pdf"
python scripts/source-alignment.py --pdf "مسار الكتاب.pdf"
```

شغّل فحص المحاذاة اللفظية بعد التدقيق البنيوي؛ فهو يضيف ملحقًا إلى تقارير المحتوى. قورن نص الصفحات آليًا لكل 2340 سجلًا، وعلّم الفحص 938 حالة منخفضة التشابه للمراجعة، لا بوصفها أسئلة خاطئة مؤكدة. النسبة اللفظية لا تثبت صحة معنى أو حكم ديني.

الكتاب ليس ضمن حزمة النشر. استخدم نسختك المصرّح بها للمراجعة. تحقق السكربت الآلي ليس فتوى أو مراجعة دينية بشرية.

## النشر على Vercel

1. ارفع ملفات المشروع إلى مستودعك، ثم اختر Import Project في Vercel.
2. الإطار: Other، الأمر: `npm run build`، مجلد الناتج: `dist`؛ هذه القيم محفوظة في `vercel.json`.
3. استخدم Node.js 24. لا توجد متغيرات سرية أو قاعدة بيانات خادم مطلوبة.
4. انشر ثم اختبر على عنوان HTTPS الناتج. النشر لم يُنفّذ من هذه المهمة، ولا يوجد رابط منشور ندّعيه.

يمكن نشر `dist/index.html` أيضًا على أي استضافة ملفات ثابتة. لا تعتمد المنصة على CDN أو خط أو صوت خارجي. لا يوجد Service Worker/PWA في هذه النسخة.

## حدود التسليم

- لا مزامنة سحابية أو مواجهة عبر الإنترنت؛ المواجهة على جهاز واحد.
- لا اختبار على Safari/Firefox أو هاتف فعلي أو Windows فعلي، ولا انتظار فعلي 45 دقيقة؛ اختُبرت المواعيد الزمنية بتسريع مضبوط.
- الأمان دفاع عن الإدخال والعرض والاستيراد، وليس إثباتًا ضد التلاعب المحلي بالنقاط. لا تُستخدم كاختبار رسمي آمن عالي المخاطر.
- الإصدار صالح للتجربة والعرض التقني وفق النتائج المرفقة؛ الاعتماد العلمي الشامل يتطلب معلم المادة.

## تحديث الاستضافة

رُفعت نسخة الإنتاج إلى فرع `gh-pages` لاحقًا بطلب المستخدم. تفعيل الرابط العام والتحقق منه لم يُؤكدا؛ الخطوة المطلوبة وحالة الشبكة في [PUBLISH_STATUS.md](PUBLISH_STATUS.md). لا يتطلب استعمال الموقع المنشور تنزيلًا أو Visual Studio Code.
