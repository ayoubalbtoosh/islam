# الألعاب التعليمية الأونلاين — ترقية 005

تضيف هذه الترقية دعم الغرف للألعاب التعليمية الـ13، باستخدام المشروع الحالي والحسابات ورموز الدعوة وسجل المواجهات الموجود. لا تحتاج مشروعًا جديدًا أو خطة مدفوعة أو Edge Functions أو Realtime.

## التفعيل على المشروع الحالي

1. تأكد من تطبيق الترقيتين 003 و004 سابقًا. لا تعِد تهيئة قاعدة البيانات أو تشغيل ترقيات التسجيل القديمة لتفعيل الألعاب.
2. افتح SQL Editor في **مشروع Supabase الحالي نفسه**. استخدم [صفحة نسخ الأجزاء الصغيرة](https://ayoubalbtoosh.github.io/islam/setup-online.html)، أو [ملفات SQL المقسمة](sql-editor/005/README.md). شغّل `00_schema.sql` ثم أجزاء المحتوى01إلى10ثم`99_verify.sql`، كل ملف وحده بصلاحية مالك المشروع. استبدل نص المحرر كاملًا في كل مرة؛ لا تلصق الأجزاء فوق بعضها. يجب أن ينتهي الفحص الأخير بـ`ready` و2179سجلًا. الملف الكامل أكبر من حدSQL Editor؛ يبقى متاحًا لأدوات سطر الأوامر فقط. يمكن إعادة تشغيل الأجزاء دون مسح الغرف أو النتائج السابقة.
3. أبقِ `config/auth.public.json` الحالي. لا تضف مفتاح خدمة أو بيانات اعتماد إدارية إلى المتصفح أو GitHub Pages. الترقية لا تغيّر ربط المدير أو تسجيل الإيميل أو سياسات الوصول إلى تقدم الطلاب.
4. بعد التطبيق، افتح حسابين مختلفين في متصفحين مستقلين. من «ألعاب» اختر الوحدة والدرس والوقت، ثم «تحدَّ صديقك أونلاين». انضم من الحساب الثاني بالرمز أو رابط الدعوة، وأكمل النشاط وتحقق من النتيجة لدى الطرفين وفي لوحة المدير. اختبر التحديث والانقطاع والانسحاب أيضًا.

**الحالة الحية:** الملف جاهز للتطبيق، لكن لم يُطبق على مشروع Supabase المستضاف ولم يُتحقق من تشغيله هناك. رفع الموقع وحده لا يطبق SQL. غياب الترقية يظهر رسالة بأن الألعاب الأونلاين بانتظار التفعيل من إدارة الموقع؛ لا يُعلن نجاح الأونلاين قبل تفعيلها واختبارها على المشروع.

## تجربة اللعب والوقت

تحتفظ كل لعبة بتفاعلها: التوصيل، والأقفال، والعجلة، والحروف، والبلاطات، والشبكة، والمنارة، والمسار، والذاكرة، وبقية الأنشطة. الغرفة توحّد نوع اللعبة ونطاق الدرس والمحتوى وموعد النهاية، مع تقدم مستقل لكل لاعب. لا تُضاف أسئلة من دروس خارج النطاق المختار.

يختار منشئ الغرفة مدة من 15 إلى 1800 ثانية، عبر مدد جاهزة أو إدخال مخصص. إذا لم يحدد مدة، يستخدم الأونلاين 180 ثانية افتراضيًا. يظهر الاختيار للطرفين داخل الغرفة، ويبدأ الوقت عند انضمامه. الموعد محفوظ على الخادم؛ إعادة التحميل أو مغادرة الصفحة لا توقفه ولا تمدده. مهلة 5 أو 10 ثوانٍ لكل عبارة «صح أم خطأ» تخص الفردي، بينما الأونلاين يعتمد وقت الغرفة المشترك.

يُحسم الفوز بالنقاط المحسوبة على الخادم، وتساوي النقاط تعادل. يمكن إنهاء لعبك وانتظار الطرف الآخر، أو الانسحاب وفق قواعد المواجهات الحالية. تبقى فجوات المحتوى المعروفة ظاهرة؛ راجع [تغطية الألعاب](../EDUCATIONAL_GAMES.md#تغطية-المحتوى-وحدودها).

## الحفظ والصلاحيات

ترقية 005 تضيف بيانات النشاط إلى الغرف وحقول نقاط الإجابات وجداول خاصة للمحتوى وإنهاء اللعب. تحافظ على الغرف والمواجهات القديمة وتقدم الحسابات. تبقى الجداول الخاصة محمية بـRLS دون منح الطالب قراءة مباشرة لها؛ العمل عبر RPC للمستخدم المسجل والمشارك في الغرفة، مع صلاحية الإدارة الحالية لسجل المدير.

يتحقق الخادم من النطاق وترتيب الإجابات والحلول الفعلية للنشاط، ولا يعتمد على نقاط أو قيمة «صحيح» يرسلها المتصفح. إعادة إرسال الإجابة نفسها لا تمنح نقاطًا إضافية. يمكن إعادة محاولة القفل الخاطئ في غرفة الهروب قبل الانتقال إلى القفل التالي. تستعيد إعادة التحميل الإجابات المسلّمة والموعد المشترك. الاختيارات غير المسلّمة (الحروف والتوصيل ورفوف الأدلة ودوران القطع) تبدأ من جديد عند العودة؛ لا يُدّعى استرجاع مسودة هذه الخطوات.

تُحفظ النتيجة بهوية الغرفة واللاعبين والنشاط والنطاق، وتبقى منفصلة عن ملف تقدم الدراسة الفردي. الضيف المؤقت لا ينشئ غرفة؛ يلزم حسابان مسجلان.

## التحقق المحلي

بعد `npm ci` والبناء وتشغيل الخادم المحلي، يمكن تشغيل اختبارات SQL والمتصفح مباشرة:

```sh
node --test supabase/tests/educational-online.test.mjs
node tests/educational-online-ui.spec.mjs
```

اختبارات SQL تستخدم PostgreSQL محليًا عبر PGlite وتشغّل الترحيلات الفعلية. اختبارات المتصفح تستخدم عميلين منفصلين مع RPC إلى قاعدة الاختبار ونقل مصادقة محاكى. نتائجها دليل محلي، وليست إثباتًا لتسجيل الدخول أو المزامنة أو تطبيق 005 على Supabase المستضاف. يحتفظ `test-results` بأدلة التشغيل التي ينشئها كل اختبار؛ لا تعد الأوامر غير المنفذة اختبارات ناجحة.

لتجديد بنك الأونلاين بعد تعديل مصادر المحتوى المعتمدة:

```sh
node scripts/seed-educational-online.mjs
```

يُحدّث هذا الأمر قسم المحتوى في ملف 005 فقط؛ لا يتصل بقاعدة البيانات المستضافة ولا يطبق الترقية.

## عند ظهور Query is too large

استخدم نسخة الأجزاء بدل الملف الكامل. كل جزء أقل من60KB ويحتوي معاملة مستقلة. صفحة النسخ لا تتصل بقاعدة البيانات ولا تؤكد تطبيق SQL تلقائيًا؛ انتقل للجزء التالي بعد رؤية Success في Supabase. إذا فشل جزء، أرسل اسمه ونص الخطأ.
