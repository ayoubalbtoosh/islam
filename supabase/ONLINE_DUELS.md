# المواجهات الأونلاين — ترقية004

هذه ترقية إضافية لمشروع Supabase الحالي بعد003. لا تعيد إنشاء الحسابات ولا تغيّر تسجيل البريد أو حفظ التقدم أو ربط المدير. لا تحتاج خطة مدفوعة أو Edge Functions أو خدمة خادم إضافية أو Realtime أو Cron.

## التطبيق على المشروع الحالي

1. إن لم تُطبّق003 بعد، اتبع تعليمات [التسجيل الحالي](README.md) أولًا؛ أنشئ حساب المدير المؤكد بنفسك قبل تلك الترقية. لا تعِد تشغيل001/002 على المشروع الموجود.
2. من SQL Editor للمشروع الحالي شغّل [004_online_duels.sql](migrations/004_online_duels.sql) كاملًا بصلاحية مالك قاعدة البيانات. يحتوي الملف مخطط المواجهات و104 أسئلة اختيار متعدد من البنك الحالي، موزعة على26 درسًا، ولا يحتاج تعديل بيانات اعتماد أو استدعاء خادم خارجي. إعادة تشغيل004 تحفظ الغرف والنتائج السابقة.
3. الإعداد العام الحالي في `config/auth.public.json` يُستخدم كما هو. لا يوضع مفتاح `service_role` أو مفتاح سري في الموقع أو فرع GitHub Pages.
4. افتح حسابين مختلفين في متصفحين مستقلين. أنشئ غرفة من الأول، وانضم برمز الدعوة من الثاني، وأكمل خمسة أسئلة على كل منهما. تحقق من النتيجة لدى اللاعبين ومن سجل المواجهات في حساب المدير. أنجز تجربة الانقطاع وإعادة الفتح أيضًا.

تطبيق SQL على المشروع المستضاف اختبار منفصل عن نشر HTML. لا تطبق GitHub Pages ترحيلات Supabase تلقائيًا.

## قواعد اللعب والحماية

- الغرفة تنتظر10 دقائق، ورمزها10 محارف سداسية عشوائية. يشارك حسابان مختلفان فقط، والانضمام يثبت تحت قفل صف قاعدة البيانات لمنع لاعب ثالث من أخذ المكان نفسه.
- تبدأ مهلة90 ثانية بوقت الخادم عند انضمام الثاني. لكل لاعب الأسئلة الخمسة نفسها، ويتقدم كل منهما مستقلًا. نقطة للإجابة الصحيحة؛ تساوي النقاط تعادل، بلا أفضلية اتصال أو توقيت للجهاز.
- الإجابات المقبولة من الخيارات الأصلية فقط، بالتتابع الصحيح، ومرة واحدة لكل سؤال. إعادة الطلب نفسه بعد انقطاع الشبكة لا تضاعف النتيجة؛ تغيير جواب سبق حفظه يُرفض.
- يحسب الخادم النقاط من نسخته الخاصة للأسئلة. لا يعيد مفاتيح الإجابات أو الشروح أو نقاط اللاعبين قبل انتهاء المواجهة. البنك التعليمي الكامل موجود أصلًا في التطبيق الفردي؛ هذه ليست منصة امتحانات مراقبة أو ادعاء حماية من الاطلاع الخارجي على المحتوى.
- انتهاء الوقت يحفظ النتيجة الحالية. الانسحاب أثناء اللعب يسجل خسارة للمنسحب، والانسحاب أثناء الانتظار يلغي الغرفة. إغلاق المتصفح أو انقطاعه وحده لا يمنح فوزًا؛ يمكن العودة قبل انتهاء المهلة.
- الغرف النشطة تُستعاد بدل إنشاء نسخ مكررة. يُسمح بحد20 غرفة جديدة للحساب خلال ساعة. رمز الدعوة ليس وسيلة لاستعراض الغرف؛ اللاعب غير المشارك لا يقرأ حالة الغرفة بمعرّفها. محاولات رموز الانضمام غير الصحيحة لا تملك عدادًا دائمًا خاصًا في هذا الإصدار؛ تستخدم بحث فهرس فقط، ويجب متابعة إساءة الاستخدام إن ظهرت.
- جداول الغرف والإجابات ومفاتيح الأسئلة خاصة وغير معروضة لواجهة Data API. لا توجد صلاحيات كتابة مباشرة للمتصفح. كل دالة تعيد فحص الهوية والتفعيل الفعليين. المدير يُتحقق منه بالربط الثابت الحالي، لا بحقل اسم أو دور يرسله العميل.
- أسماء اللاعبين فقط تظهر للخصم. المدير وحده يتلقى أسماء وبريد المشاركين والوقت والحالة والنتيجة المحفوظة، بصفحات20 سجلًا افتراضيًا وحد أقصى100. لا تُعاد كلمات مرور أو رموز جلسات أو صفوف Auth الكاملة.
- النتائج تحفظ مستقلة عن `user_progress`؛ لا تكتب المواجهة فوق تقدم الدراسة أو فوق إجابات شخص آخر. حذف حساب Auth له آثاره المرجعية المعتادة: حذف المضيف يحذف غرفه، وحذف الضيف يزيل ربطه؛ صدّر السجلات أولًا إذا كان الاحتفاظ بها بعد حذف الحساب مطلوبًا.

## عقد API

| الدالة | النتيجة |
| --- | --- |
| `duel_create()` | ينشئ غرفة أو يستعيد الغرفة الجارية للحساب |
| `duel_join(p_code)` | ينضم برمز الدعوة أو يستعيد عضوية الضيف الحالية |
| `duel_state(p_room_id)` | حالة خاصة بالمشارك وسؤاله الحالي فقط |
| `duel_answer(p_room_id,p_question_id,p_answer)` | يحفظ إجابة JSON نصية تحمل معرّف الخيار مثل `"o1"` ويعيد الحالة |
| `duel_leave(p_room_id)` | إلغاء الانتظار أو تسجيل انسحاب اللاعب |
| `duel_recent()` | مصفوفة آخر20 غرفة للحساب، ومنها الغرفة الجارية |
| `platform_admin_duels(p_limit,p_offset)` | `{rooms,total,limit,offset}` للمدير فقط |

الحالة تعيد `id,code,status,host_id,guest_id,created_at,expires_at,started_at,deadline,finished_at,server_now,question_count,players,me,question,result`. اللاعب يتضمن `id,name,answered,score,finished`؛ `score` يظل `null` حتى اكتمال الغرفة. السؤال يتضمن `id,prompt,options` فقط. النتيجة تشمل `winner_id` (أو`null` للتعادل)، و`reason` (`answered/timeout/forfeit`)، و`scores`.

## استهلاك الخطة المجانية والاحتفاظ

لا توجد اشتراكات Realtime أو عمليات دائمة. تتحدد النهاية داخل طلب الحالة التالي، بما فيه طلب المدير. الاقتراع يحتاج طلب حالة واحدًا كل نحو3 ثوانٍ فقط أثناء عرض غرفة جارية، ويتوقف بعد انتهاء الغرفة أو إخفاء الصفحة. لا يُكتب ملف الطالب من كل طلب حالة. لاعبان في مواجهة90 ثانية يولدان نحو60 طلب حالة مع طلبات الإجابة، دون وعد بسعة غير محدودة؛ حدود الخطة الفعلية تُتابع من لوحة Supabase.

تُحفظ النتائج إلى أن يحذفها المالك. لا تمسح004 السجلات تلقائيًا ولا تحتاج Cron مدفوعًا. عند اقتراب حد التخزين، صدّر السجلات المطلوبة من SQL Editor ثم نظّف الغرف النهائية القديمة فقط بعد اختيار مدة الاحتفاظ، مثل90 يومًا. حذف صف الغرفة يحذف إجاباته المرجعية أيضًا. لا تمسح `user_progress` أو `auth.users` لتنظيف المواجهات، ولا تضف صلاحيات حذف للمتصفح. يمكن فحص الحجم من لوحة Database قبل اتخاذ قرار التنظيف.

## الاختبار وإعادة توليد بنك الأسئلة

```sh
node scripts/seed-duels.mjs
npm run test:online:sql
```

السكربت يحدّث قسم الأسئلة المعلَّم داخل004 من `data/questions.json`، ولا يقرأ مستخدمين أو أسرارًا. غرف موجودة تحتفظ بنسخة الأسئلة الخاصة بها ولا تتغير أثناء اللعب عند تحديث البنك.

اختبارات PostgreSQL/PGlite تغطي الترقية المتكررة وحفظ الحسابات والتقدم، والصلاحيات والخصوصية، والانضمام والاستعادة والعضوية، وصحة الإجابات وترتيبها وتكرار الطلب، وحساب الفوز والتعادل والنتيجة الإدارية، والمهلة والانسحاب وانتهاء الغرفة وتعطيل الحساب وحد الإنشاء. هذه أدلة محلية بمحاكاة نقل هوية Auth؛ لا تثبت تطبيق الترقية أو دخول حسابين أو وصول جهازين فعليين إلى مشروع Supabase المستضاف.
