# تحدّي التوجيهي | التربية الإسلامية — 2.2

**إنشاء الطالب أيوب محمد البطوش**

منصة تحديات وامتحانات متجاوبة، مبنية من ملف HTML الأصلي، مع تسجيل مفتوح بحساب Google مُجهّز للتفعيل، ووضع ضيف مؤقت. النسخة الحالية لا تدّعي أن حسابات Google أو المزامنة السحابية تعمل قبل إنشاء خدمة الحسابات وربطها.

## استعمال الموقع

بعد النشر، افتح رابط الموقع من أي متصفح؛ لا يحتاج الطالب تنزيلًا أو Visual Studio Code.

- **ضيف:** يتدرب دون تسجيل، وتُمسح تجربته عند التحديث أو الإغلاق. لا تُحفظ نتائج الضيف أو تُرحل إلى حساب آخر.
- **حساب:** بعد تطبيق002 وتفعيل Google، يستطيع أي حساب Google مؤكد التسجيل تلقائيًا كطالب دون إضافة بريده مسبقًا. الحسابات اليدوية السابقة بالبريد وكلمة المرور تبقى مدعومة.
- **مدير:** لوحة للحسابات المسجلة تلقائيًا والإيميلات والأسماء والدخول والتعطيل، دون كلمات مرور. الإيميل الإداري المطلوب يهيأ عبر SQL owner فقط: `ayobalbtoosh41@gmail.com`.
- **التقدم:** للحساب تخزين محلي معزول ومزامنة سحابية مع كشف تعارض الأجهزة. عند تعذر المزامنة لا يُعلن نجاح حفظ سحابي، وتظل نسخة هذا الحساب على الجهاز عند توفر التخزين.

**خطوة التفعيل المتبقية:** تطبيق SQL في مشروع Supabase الذي أنشأه المستخدم وإعداد مزودي Email/Google، ثم إضافة URL والمفتاح العام وإعادة النشر. [AUTH_SETUP.md](AUTH_SETUP.md) يوضح الخطوات، و[supabase/README.md](supabase/README.md) يوضح ضوابط الخادم. لا تضع مفاتيح خدمة أو كلمات مرور في ملفات الموقع.

## الألعاب والمحتوى

الأوضاع الـ11 الأصلية متاحة، مع ست واجهات للأسئلة: اختيار فردي، صح/خطأ، اختيار متعدد، توصيل، ترتيب، فراغ بالاختيار. الامتحان 45 دقيقة إجمالية مع رجوع وتعديل وتسليم مؤكد. المواجهة على جهاز واحد، بالتناوب والاستعداد، وعدد محدد لكل لاعب.

4 وحدات، 26 درسًا، 2340 سجلًا سليم البنية، 2314 متاحًا للعب، و26 مسودة مستبعدة محفوظة. عنوان الفئة الظاهر «توجيهي»؛ **مصدر البنك الفعلي كتاب الصف الحادي عشر/الفصل الثاني**. لم تُبدل الأسئلة إلى كتاب آخر ولم يُدّعَ اعتماد علمي شامل. المقارنة الدلالية مع الكتاب عينة 52 سؤالًا، والفحص اللفظي الآلي شمل كامل البنك. راجع تقارير المحتوى.

## تشغيل المطور والبناء

يتطلب البناء Node.js 24 الموصى به (الحد الأدنى 22.8) وnpm:

```sh
npm ci
npm run build
npm start
```

الخادم على المنفذ 4173. `index.html` و`standalone.html` و`dist/index.html` ملفات مولدة، تحتوي البيانات والعميل الرسمي Supabase SDK المجمّع محليًا؛ لا تعتمد على CDN. عدّل `src` ثم أعد البناء. النسخة المستقلة مناسبة للتدريب كضيف؛ OAuth يتطلب رابط HTTP/HTTPS معتمدًا، وليس file://.

اختبارات SQL الفعلية المحلية وتعليمات تكرارها في [supabase/TEST_RESULTS.md](supabase/TEST_RESULTS.md). لا يحتاج الموقع مكتبة اختبار PostgreSQL في الإنتاج.

## الملفات الرئيسية

- `src/core.js`: قواعد الأسئلة والدوران والنقاط.
- `src/storage.js`: تخزين الضيف والحسابات وعزل النطاقات.
- `src/auth.js`: العميل الرسمي، التحقق من السماح، المزامنة، الإدارة.
- `src/controller.js`: الجلسات والمؤقت والامتحان والتهيئة.
- `src/ui.js` و`src/styles.css`: الواجهات العربية والحسابات والإدارة والمظهران.
- `config/auth.public.json`: عنوان المشروع والمفتاح العام فقط؛ أضافهما صاحب المنصة، ولا يتضمن أسرار إدارة.
- `supabase/`: SQL والسياسات وخطاف التسجيل المفتوح وتهيئة المدير وأدوات القائمة والاختبارات.
- `data/`: البنك الكامل والمؤهل والمسودات والتوثيق.
- `reference/original.html`: المرفق الأصلي للمقارنة.
- `tests/` و`test-results/`: الاختبارات والأدلة الفعلية؛ التقارير تميز النتائج القديمة والجديدة.
- `vercel.json`: نشر ملفات ثابتة إلى `dist`؛ يمكن استخدام GitHub Pages أيضًا.

## تغيير السياسة الحالي

المستخدم اختار السماح لأي Google بدل قائمة الإيميلات. المشروع الحالي يحتاج تشغيل supabase/migrations/002_open_google_signup.sql مرة واحدة؛ إيقاف Hook وحده لا يغيّر سياسات الوصول القديمة. Google يجب أن يكون External / In production لاستقبال غير Test users. الترقية المحلية والواجهة اختبرتا دون تسجيل حي.
